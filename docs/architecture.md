# Architecture decisions

Culverin is a browser-local Chrome Manifest V3 extension. GitHub supplies repository metadata and source archives; the extension analyzes source in the browser. There is no Culverin server, native companion, or telemetry service.

## Extension boundaries

- The TypeScript service worker owns GitHub requests, credentials, job coordination, and cancellation. Packaged options-page controls, the extension popup, and GitHub content-script controls have separate sender gates. Public page requests must come from a top-level GitHub document and match the tab's current repository overview URL, which can change within the same document. Popup requests and replies travel on a long-lived port that the service worker accepts only from the packaged `popup.html`, whether Chrome shows it as the toolbar popup or in a tab. Chrome omits frame and document IDs for the toolbar popup, so the port itself identifies the popup; the popup reconnects on its next request after a service-worker restart. Lookup, status, and Analyze requests are checked against the active GitHub repository tab; a cancel request only needs to name that tab's running popup analysis, so switching tabs neither cancels the analysis nor prevents a later cancel. Auth controls remain options-only. The worker binds each subscription to its tab or extension document, navigation, and request IDs.
- The GitHub content script adds one Shadow DOM row to the About list on supported repository overviews, including URLs with fragments. The script runs at `document_start` and starts the lookup as soon as GitHub's repository marker in the document head names the current repository, so metadata resolution overlaps page loading; the About forks row is a fallback trigger for same-document navigation. A page adapter anchors the row after the visible About forks row, and waits until GitHub's enclosing React app is marked loaded so the row never interferes with hydration; when the About sidebar is hidden, as in narrow layouts, no row is shown. The row uses GitHub's color variables and the pixel-aligned monochrome icon [`assets/mono/culverin-mono-stats.svg`](../assets/mono/culverin-mono-stats.svg), bundled into the content script and drawn in `currentColor`, so it matches the neighboring repository stats, with a compact total and the exact total in its tooltip. Fragment changes and GitHub sidebar re-renders keep the same view and move the row back into place. A bounded URL check detects same-document route changes even without DOM mutations; DOM mutations and window resizing remain recovery signals. Lookup resolves metadata and may show a compatible complete cached total without downloading an archive; otherwise the row offers to count lines of code. A trusted click on that row, like the popup's Analyze action, permits a SHA-specific source snapshot download. While a page analysis runs, the row shows its progress and a trusted click cancels it. A trusted click on a complete total asks the service worker to open the toolbar popup for the active tab with `chrome.action.openPopup`, which needs no extra permission; on Chrome versions before 127, where extensions cannot open their popup, the click has no effect. A failed analysis offers a retry, a rate limit shows a notice until its retry time, and size limits, unsupported snapshots, and partial results show a notice without a total. A lookup that finds a private, unavailable, or empty repository hides the row. The toolbar popup contains the full analysis UI; its explicit Analyze action permits a SHA-specific source snapshot download. A popup analysis belongs to its repository tab rather than to the popup document: closing the popup does not cancel it, and a reopened popup on the same tab resumes its progress and result through `analysis.status`. Navigating that tab away from the repository or closing it cancels the analysis. After a complete result, the service worker sends the code-line total to the matching repository page. The content script can read a compatible public aggregate cache result or its own page analysis result, but renders only the code-line total and never receives credentials, archive URLs, or source files. The packaged options page exposes cache controls and retains trusted analysis and access checks.
- Public page messages use a closed version-1 request and reply protocol. A lookup returns a cache hit or miss after a compatible resolution confirms public visibility. A page may also ask the service worker to open the toolbar popup; the popup port rejects that request. Resolution metadata, including its timestamp, lives outside the deterministic result. Both worker and page validate result identity against the resolution before display. One archive analysis runs at a time; identical explicit requests share it, while distinct requests wait in a bounded queue. Public page analysis uses unauthenticated GitHub requests and does not display private-repository results.
- An offscreen document hosts a dedicated, terminable analysis worker. The service worker transfers bounded archive chunks to it with acknowledgments. The worker decompresses gzip, validates tar entries, applies file limits, and calls a fresh Rust/WASM counter for each job. The service worker receives the aggregate result and transport diagnostics, not source files.
- The Rust counter uses Tokei and exposes the same counting boundary to native tests and browser WASM. The result contract is [`schemas/analysis-result-v1.schema.json`](../schemas/analysis-result-v1.schema.json). Counting rules, coverage, archive handling, and resource limits are specified in [result semantics](result-semantics.md). An interrupted, canceled, malformed, or resource-limited job returns a failure rather than a complete result.

## Storage and packaging

- A personal access token, when supplied, is held in trusted extension contexts through `chrome.storage.session`. Complete public aggregate results are stored in trusted-only `chrome.storage.local`, bounded to 200 entries or 5 MiB. Cache identity includes repository ID, commit SHA, engine and wrapper versions, rules profile/version/hash, coverage policy, and result schema. Mutable names and branch labels remain resolution metadata. Ref resolutions are held in memory for at most 60 seconds, 100 entries, or 512 KiB. A confirmed public-to-private transition purges persistent results for that repository; unresolved visibility never authorizes a cache display. The service worker keeps only bounded subscriber interruption markers in session storage. Partial results, private results, archives, and source files are not persisted locally.
- The coordinator permits one active archive analysis, eight queued jobs with a 30-second queue wait, and 32 subscriptions overall. A subscription belongs to one document/navigation, one repository tab for popup analyses, or the trusted options page. Service-worker restart reports interruption and requires a new explicit Analyze action; it does not resume an archive download.
- The manifest is explicit in `extension/public/manifest.json`. It declares `storage` and `offscreen` permissions; GitHub, GitHub API, and codeload host access; and a packaged-code CSP that permits local WASM. The action opens a packaged popup that reads the active tab using the existing GitHub host permission; no `tabs` permission is added. Vite builds the service worker, popup, options page, offscreen document, analysis worker, and packaged WASM asset. Bun bundles the content script as a classic script because Chrome's manifest content-script entry cannot load Vite's split ESM chunks. Neither build path changes the manifest's permissions.
- Chrome 120 is the minimum supported version. Bun 1.4.2 runs the TypeScript build and checks; Cargo runs native Rust tests; direct WASM tests exercise the generated module; and Playwright smoke tests load the packaged extension in Chromium.
