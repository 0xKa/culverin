# Architecture decisions

Culverin is a browser-local Chrome Manifest V3 extension. GitHub supplies repository metadata and source archives; the extension analyzes source in the browser. There is no Culverin server, native companion, or telemetry service.

## Extension boundaries

- The TypeScript service worker owns GitHub requests, credentials, job coordination, and cancellation. Packaged options-page controls and GitHub content-script controls have separate sender gates. Public page requests must come from the top-level repository overview document and match its URL; auth controls remain options-only. The worker binds each public subscription to its tab, document, navigation, and request IDs.
- The GitHub content script mounts one minimal Culverin control on supported repository overviews. It resolves the default branch for display without downloading an archive. Analyze is the explicit action that downloads a SHA-specific source snapshot; Cancel and navigation abort the active subscription. A document-bound port detects page departure, and a bounded watchdog marks lost responses as interrupted. The script receives aggregate results, progress, and safe error codes, never credentials, archive URLs, or source files. The packaged options page remains a trusted analysis and credential harness.
- Public page messages use a closed version-1 request and reply protocol. A lookup returns a cache miss until local result caching is implemented. Resolution metadata, including its timestamp, lives outside the deterministic result. Both worker and page validate result identity against the resolution before display. One repository job may run at a time; additional work receives an explicit busy error. Public page analysis uses unauthenticated GitHub requests and does not display private-repository results.
- An offscreen document hosts a dedicated, terminable analysis worker. The service worker transfers bounded archive chunks to it with acknowledgments. The worker decompresses gzip, validates tar entries, applies file limits, and calls a fresh Rust/WASM counter for each job. The service worker receives the aggregate result and transport diagnostics, not source files.
- The Rust counter uses Tokei and exposes the same counting boundary to native tests and browser WASM. The result contract is [`schemas/analysis-result-v1.schema.json`](../schemas/analysis-result-v1.schema.json). Counting rules, coverage, archive handling, and resource limits are specified in [result semantics](result-semantics.md). An interrupted, canceled, malformed, or resource-limited job returns a failure rather than a complete result.

## Storage and packaging

- A personal access token, when supplied, is held in trusted extension contexts through `chrome.storage.session`. The service worker keeps only short-lived job state and a session interruption marker. Analysis results and source archives are not persisted as a cache.
- The manifest is explicit in `extension/public/manifest.json`. It declares `storage` and `offscreen` permissions; GitHub, GitHub API, and codeload host access; and a packaged-code CSP that permits local WASM. Vite builds the service worker, options page, offscreen document, analysis worker, and packaged WASM asset. Bun bundles the content script as a classic script because Chrome's manifest content-script entry cannot load Vite's split ESM chunks. Neither build path changes the manifest's permissions.
- Chrome 120 is the minimum supported version. Bun 1.4.2 runs the TypeScript build and checks; Cargo runs native Rust tests; direct WASM tests exercise the generated module; and Playwright smoke tests load the packaged extension in Chromium.
