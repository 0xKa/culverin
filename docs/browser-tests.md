# Extension browser checks

`bun run test:browser` builds the extension and runs `tests/browser-smoke.ts`. The runner reports each scenario name and stops with that name on failure. Shared support owns exact artifact and permission/CSP checks, profile setup and cleanup, routed GitHub fixtures, and action-popup controls. `CULVERIN_EXTENSION_DIR` selects an extracted package for the same checks, and `CHROME_BIN` selects Chromium.

Scenarios execute sequentially in one browser profile. Setup installs deterministic routes and discovers the extension. Page/popup lifetime checks establish navigation, hydration, cancellation, and no-request-on-open behavior. Result checks establish displayed totals, disclosures, cache reuse, and reanalysis retention. Ignore/access checks exercise rules and trusted sender boundaries. Partial-result checks cover oversized files and compatibility with cached count-only results. Acquisition checks cover chunking, worker interruption, viewer detach, and recovery. Diagnostic checks exercise direct archive/counter fixtures, leases, synthetic blocking, WASM traps, fresh memory, and restart reconciliation. Page-counting checks cover explicit and opt-in counting, rate limits, and accessibility. GitHub/Storage checks cover device flow, token staging, account boundaries, scoped clearing, and remembered sections.

Mutable GitHub fixture data is a typed `FixtureState` shared by reference. Scenario inputs and returned values are typed; browser-evaluated functions keep serialized arguments explicit. The restart scenario shares its mutable version ID through an object so later scenarios see service-worker updates. Request-count assertions retain the original sequence; scenarios must not run concurrently against that profile.

All network acquisition is routed by default. `CULVERIN_LIVE_PUBLIC=1` explicitly enables the additional public-GitHub scenario. Real credentials are never required. Profile cleanup runs after scenario failure, and browser startup failure also removes its temporary profile. Screenshots generated by the suite remain under ignored local output paths.
