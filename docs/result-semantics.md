# Counter result semantics

Culverin counts selected in-memory files with Tokei 15.0.0. The deterministic result contract is [`schemas/analysis-result-v1.schema.json`](../schemas/analysis-result-v1.schema.json); `counter/src/lib.rs` produces it and `extension/src/counter/result.ts` validates its structure and cross-field invariants. Results identify Tokei, wrapper version `1`, the `source-v1` rules profile, rules version `1`, and coverage policy version `1`. They are Tokei results. They are not normalized to `cloc` or GitHub Linguist, which use different recognition and counting policies.

## Input and attribution

The boundary accepts relative slash-separated paths and bytes. It rejects empty, absolute, dot-segment, backslash, NUL, and overlong paths. `classify_path` uses a bounded prefix to detect paths and shebangs; `add_file` repeats classification and inspects the full body for NUL bytes. Ordinary NUL-containing files are binary skips. UTF-16 BOM files are decoded first, so their NUL bytes do not make them binary. UTF-8 BOM is stripped; malformed UTF-8 and UTF-16 use replacement decoding and mark coverage `counter_inaccurate`. The current in-memory Tokei API has no per-slice `inaccurate` flag; the wrapper surfaces decoding uncertainty explicitly. Invalid notebook data can produce zero counts through Tokei's parser; the wrapper validates its expected cell and metadata shape and marks the result `counter_inaccurate`.

One eligible regular file increments `countedFiles` and exactly one language row's `files`: its primary Tokei language. Child rows for embedded languages always have `files: 0`. The counter attributes child lines to their child language. For HTML, Vue, Svelte, and notebooks, Tokei's parent counts include child counts, so the wrapper subtracts those child counts from the parent. For inline embedding on a physical line, child attribution takes precedence and any remaining duplicate count is removed from the primary language. Markdown already separates fenced child lines from its own lines. This produces one physical line total per text file in the accepted corpus while preserving Tokei's code, comment, and blank classifications as far as possible. Notebook cell source lines are logical source lines rather than lines of notebook JSON. Empty files still count as one file with zero lines; whitespace-only files count blank lines.

The accepted corpus includes Rust, TypeScript, Markdown fences, HTML, Vue, Svelte, notebooks, extensionless Python shebangs, UTF-8 BOM, UTF-16, malformed UTF-8, binary data, empty files, and built-in and custom exclusions. Native and browser-WASM runs consume the same path, byte, and rules fixtures. Unknown extensions and unrecognized extensionless files are `unsupported_language`. `oversized_source` marks an eligible file above 8 MiB as skipped and makes coverage partial. Excluded files do not make coverage partial. Other failures, including traps and invalid inputs, do not return a result.

## Rules and identity

The profile excludes known dependency, cache, generated-output, and build directories and common lock, map, and minified files. The exact current lists are in `extension/src/counter/rules.ts` and mirrored at the Rust boundary. Exclusion matching is currently a literal path-prefix subset; the complete glob matcher is a later archive-engine decision. `.gitignore` is not read. Directories such as `vendor` and `build` can contain original work; excluding them is a declared profile choice.

Custom exclusions are relative slash-separated literals, capped at 64 patterns, 256 bytes per pattern, and 4096 total bytes. They are sorted and deduplicated. The effective rules hash is SHA-256 of the UTF-8 JSON encoding of `["source-v1","1",normalizedExclusions]`. The cache identity includes schema version, counter name and version, wrapper version, rules version and hash, and coverage policy version. Changing any counting or classification policy requires an appropriate version bump. Result fields retain no paths, timestamps, or transport metrics.

## Browser dependency

Tokei is pinned to the exact crates.io release `15.0.0` with CLI features disabled. Its transitive `home` 0.5.12 crate lacks a `wasm32` fallback, so [`patches/home`](../patches/home) is a copy of that crate with one target-specific `home_dir_inner()` implementation returning `None`. The crate's MIT and Apache licenses are preserved. Remove the patch when upstream `home` supplies a browser-target fallback and Tokei can compile unchanged. The `wasm-bindgen` glue has a singleton initialization guard; the build script copies generated glue and removes only that guard so each serialized job instantiates fresh WASM memory. The generated source remains untouched.
