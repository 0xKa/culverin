# Architecture decisions

Culverin is a browser-local Chrome Manifest V3 extension. GitHub supplies repository metadata and source archives; the extension analyzes source in the browser. There is no Culverin server, native companion, or telemetry service.

## Extension boundaries

- The TypeScript service worker owns GitHub requests, credentials, job coordination, and cancellation. Packaged settings-page controls, the extension popup, and GitHub content-script controls have separate sender gates. Public page requests must come from a top-level GitHub document and match the tab's current repository overview URL, which can change within the same document. Popup requests and replies travel on a long-lived port that the service worker accepts only from the packaged `popup.html`, whether Chrome shows it as the toolbar popup or in a tab. Chrome omits frame and document IDs for the toolbar popup, so the port itself identifies the popup; the popup reconnects on its next request after a service-worker restart. Lookup, status, and Analyze requests are checked against the active GitHub repository tab; a cancel request only needs to name that tab's running popup analysis, so switching tabs neither cancels the analysis nor prevents a later cancel. When Chrome reports no active tab in its last-focused window while the toolbar popup is focused, only that toolbar sender may fall back to the active tab in the requested repository tab's browser window; another focused tab, an inactive requested tab, and popup documents opened in tabs retain the original rejection checks. Only the settings page can connect, disconnect, or clear private results. The worker binds each subscription to its tab or extension document, navigation, and request IDs.
- The GitHub content script adds one Shadow DOM row to the About list on supported repository overviews, including URLs with fragments. The script runs at `document_start` and starts the lookup as soon as GitHub's repository marker in the document head names the current repository, so metadata resolution overlaps page loading; the About forks row is a fallback trigger for same-document navigation. A page adapter anchors the row after the visible About forks row, and waits until GitHub's enclosing React app is marked loaded so the row never interferes with hydration; when the About sidebar is hidden, as in narrow layouts, no row is shown. The row uses GitHub's color variables and the pixel-aligned monochrome icon [`assets/mono/culverin-mono-stats.svg`](../assets/mono/culverin-mono-stats.svg), bundled into the content script and drawn in `currentColor`, so it matches the neighboring repository stats, with a compact total and the exact total in its tooltip. Fragment changes and GitHub sidebar re-renders keep the same view and move the row back into place. A bounded URL check detects same-document route changes even without DOM mutations; DOM mutations and window resizing remain recovery signals. When the local cache holds no result for the page's owner and name under the current rules, a page lookup makes no GitHub request and the row offers to count lines of code; if an earlier request hit the rate limit and its retry time has not passed, the row shows the rate-limit notice instead. Otherwise the lookup resolves metadata and may show a compatible cached total without downloading an archive, or offers to count when the commit or rules no longer match. A Counting setting can instead count when the page opens: the lookup then always resolves metadata, and on a cache miss the service worker tells the content script to start the same analysis a click would. It does so at most once per repository, commit, and rules per browser session, tracked in session storage and reset by clearing public or all saved results, so a failed or canceled count is not repeated on every visit. A trusted click on that row, like the popup's Analyze action, permits a SHA-specific source snapshot download. While a page analysis runs, the row shows its progress and a trusted click cancels it. Downloading, unpacking, and counting overlap, so progress only moves forward through those phases: once counting has started, a later download update does not bring back the downloading label. A trusted click on a complete total asks the service worker to open the toolbar popup for the active tab with `chrome.action.openPopup`, which needs no extra permission; on Chrome versions before 127, where extensions cannot open their popup, the click has no effect. A failed analysis offers a retry, a rate limit shows a notice until its retry time, and size limits and unsupported snapshots show a notice without a total. When source files were too large to count, the total ends with `+` and its tooltip says how many files it leaves out; the popup shows the same note above the full result. A lookup that resolves an empty repository hides the row. When GitHub reports a repository as missing, which is how a private repository looks without access, the row says that it may be private and a trusted click asks the service worker to open the GitHub section of the settings page in a new tab; with a connection, the row instead suggests checking which repositories the connection can read. The toolbar popup contains the full analysis UI; its explicit Analyze action permits a SHA-specific source snapshot download. Opening the popup makes no GitHub request: its lookup reads only resolutions kept from the last 20 minutes. Without one, the popup shows the repository name and Analyze, and Analyze resolves metadata before counting. Once a result is shown, the button reads Reanalyze; Reanalyze resolves metadata again even within the 20-minute window, shows the cached result when the commit and rules are unchanged, and otherwise downloads and counts the new commit. Alongside code lines, the popup shows text lines, the prose lines of documentation formats defined in [result semantics](result-semantics.md). Its details list files that are not recognized as a language by extension, with their line counts, in an Other files section that does not add to code or text lines. The popup header shows how many core API requests remain out of the hourly limit, such as `API 57/60`, or the connected account's limit once a connection is used, and the Counting settings show the same count with its reset time, updating while open. Beside each count, a small bar fills with the share left and turns amber once half the limit is used and red at 80%. The service worker reads the count from the `x-ratelimit-*` headers of its lookup responses, including rate-limited ones, so showing it costs no extra request; it keeps the lowest count seen for the current reset window, tags counts from authenticated requests, and does not let an anonymous fallback request replace a connected account's count, and the popup shows the full limit once the reset time passes. Archive downloads are not counted, because GitHub tracks them separately from the core limit. When a kept resolution exists, the popup shows the repository size that GitHub reports in its metadata, which includes Git history and needs no archive download; an analysis result, including a cached one, adds the total size of the regular files at the analyzed commit. A popup analysis belongs to its repository tab rather than to the popup document: closing the popup does not cancel it, and a reopened popup on the same tab resumes its progress and result through `analysis.status`. Navigating that tab away from the repository or closing it cancels the analysis. After a result, the service worker sends the code-line total and the number of files too large to count to the matching repository page. The content script can read a compatible public or private aggregate cache result or its own page analysis result, but renders only the code-line total and never receives credentials, archive URLs, or source files. The packaged settings page exposes the Culverin ignore settings, controls to clear public, private, or all saved results and read-only lists of saved public and private results in its Storage section, the GitHub connection in its GitHub section, and in its Counting section whether counting starts on an explicit action, the default, or when a repository page opens. The Counting choice is stored in trusted-only `chrome.storage.sync` only when it differs from the default. The saved results list reads the public cache from trusted-only `chrome.storage.local`, keeps only entries that pass the cache's own validation, and shows each repository, commit, code lines, files, main language, whether custom ignore rules applied, and when it was counted and last viewed, with the storage used against the cache limits; it makes no GitHub request and updates when the cache changes. Its About section shows the extension version from the manifest, the Tokei and rules versions, the Chrome major version, and the extension ID, with links to the repository, changelog, privacy policy, issues, license, and the packaged third-party notices; Copy details writes those values to the clipboard only when the user selects it. A sidebar switches between sections through the URL fragment, such as `settings.html#storage`. Without a known fragment, the page opens the section last shown, which it keeps in the extension origin's `localStorage`, or else the first sidebar section; the popup's Culverin ignore Edit action selects that section before opening the page. The service worker ignores the fragment when it checks that a request comes from the settings page. Culverin ignore turns built-in exclusion groups on or off and adds custom exclusions; the settings page writes them to `chrome.storage.sync`, restricted to trusted extension contexts. The service worker reads the current settings for each lookup and analysis, uses their rules hash for cache and job identity, and passes the rules to the analysis worker; results counted under other settings remain cached but are not shown. When the settings differ from the defaults, the popup summarizes them with a link to the settings page, and a lookup that finds only results counted under other settings says that the rules changed. The content script never reads the settings; it compares a result's rules hash with the default hash only to add a Culverin ignore note to the row's tooltip.
- Public page messages use a closed version-1 request and reply protocol. A lookup returns a cache hit or miss after a compatible resolution confirms public visibility; a page lookup without a cached result returns `repository.not_cached` without resolving, and a cache miss may carry `autoCount` when the Counting setting counts on page open. A popup lookup never resolves: it returns a cache hit or miss from a resolution kept in the last 20 minutes, or `repository.not_cached` without one. Only popup analysis requests may carry `reanalyze: true`, which bypasses the kept resolution. A page may also ask the service worker to open the toolbar popup; the popup port rejects that request. Resolution metadata, including its timestamp and GitHub's reported repository size, lives outside the deterministic result. Both worker and page validate result identity against the resolution before display. One archive analysis runs at a time; identical explicit requests share it, while distinct requests wait in a bounded queue. Page and popup replies may carry public or private resolutions; the aggregate result is the same either way.
- A GitHub connection is optional. Without one, every request is anonymous. The settings page offers two ways to connect. The preferred one is the device flow of the Culverin GitHub App, whose only repository permissions are Contents and Metadata, both read-only: the service worker requests a device code from `github.com/login/device/code` with the app's public client ID, the settings page shows the user code with a link to `https://github.com/login/device`, and the page asks the service worker to poll `github.com/login/oauth/access_token` at the interval GitHub sets until the user approves, declines, or the code expires. No client secret exists in the extension. The fallback is a personal access token, preferably fine-grained with read-only Contents access: the settings page writes it with a random submission ID to trusted-only session storage, where it waits at most 60 seconds, and the service worker reads and deletes it, checks it with `GET /user`, and saves it. Both flows record the GitHub login for display. The connection lives in trusted-only `chrome.storage.local` as a single record with a generation ID, so it survives browser restarts without asking again. App tokens expire after 8 hours; the service worker refreshes them with the refresh token, which GitHub allows without a client secret for device-flow tokens, one refresh at a time and at most 5 minutes before expiry, and keeps the old token until it expires if GitHub is unreachable. A refresh that GitHub rejects, or a 401 from any request, marks the connection expired: the tokens are deleted, the login is kept to explain what happened, and requests fall back to anonymous. Connecting, disconnecting, expiry, and clearing private or all results each start a new generation; the service worker aborts jobs from the old generation, drops kept resolutions and the stored rate limit, and a connection attempt that started under an older generation is discarded. Disconnecting, and connecting a different GitHub account, also delete private results. Tokens stay in the service worker and settings page: content scripts, the popup, the offscreen document, and analysis workers never receive them, and archive redirects carry GitHub's own signed URLs rather than the token.
- With a connection, page and popup lookups resolve metadata with the token, so they count against the account's limit of 5,000 requests per hour. Kept resolutions are keyed by generation. If the token cannot see a repository, the service worker retries once anonymously so public repositories keep working even where the app is not installed. A private resolution selects the private result cache and a job whose identity includes the generation, and the archive is downloaded with the token; public archives are downloaded anonymously. A private resolution also removes any public result and public resolution for that repository. When a connected lookup reports a repository as missing, private results saved under that name are deleted. Rate-limit waits are tracked separately for anonymous requests and for each generation.
- An offscreen document hosts a dedicated, terminable analysis worker. The service worker transfers bounded archive chunks to it with acknowledgments. The worker decompresses gzip, validates tar entries, applies file limits, and calls a fresh Rust/WASM counter for each job. The service worker receives the aggregate result and transport diagnostics, not source files.
- The Rust counter uses Tokei and exposes the same counting boundary to native tests and browser WASM. The result contract is [`schemas/analysis-result-v2.schema.json`](../schemas/analysis-result-v2.schema.json). Counting rules, coverage, archive handling, and resource limits are specified in [result semantics](result-semantics.md). An interrupted, canceled, malformed, or resource-limited job returns a failure rather than a complete result.

Slow actions share a packaged CSS spinner between the Preact popup/settings UI and the content script's Shadow DOM. The popup shows it beside analysis phases for an initial analysis and beside the disabled Reanalyze button when refreshing a result. Reanalyze keeps the existing totals, sizes, commit, and details displayed until a replacement result is ready, preserving the details disclosure state; unchanged commits, errors, and cancellation retain the current result. Its status starts with “Checking for updates…” and advances through analysis phases if needed; the repository row replaces its icon with the spinner only while analysis is running. Both retain their cancellation controls. GitHub settings show it only while requesting a connection code or validating a token, with disabled controls and action-specific button text. Waiting for the user to approve the GitHub code remains a static message. The spinner is hidden from assistive technology, which receives the existing status text, respects reduced motion, and follows the surrounding text color in light, dark, and forced-color modes. See [loading indicators](loading-indicators.md) for manual checks.

## Storage and packaging

The Storage settings place each individual clear button beside its public or private results heading, with a separate Clear all results button below both lists. Clearing results preserves ignore and Counting settings and the GitHub credential. Clearing public results removes the public result cache, kept resolutions, and session automatic-count attempts; clearing private results uses the existing generation change to abort old private jobs and remove their saved results. Clearing all results combines both actions. These requests are accepted only from the packaged settings page and never start a download.

- Culverin makes anonymous GitHub requests unless the user connects GitHub. The connection record, including its tokens, is stored in trusted-only `chrome.storage.local`, and a token entered on the settings page waits in trusted-only `chrome.storage.session` for at most 60 seconds, as does the pending device code. Culverin ignore settings are stored in trusted-only `chrome.storage.sync`, which Chrome syncs with the user's other browsers when Chrome sync is on. Public aggregate results are stored in trusted-only `chrome.storage.local`, bounded to 200 entries or 5 MiB. Private aggregate results are stored under a separate key, bounded to 100 entries or 2 MiB, and are shown only after a lookup with the current connection confirms the repository is still private and readable at the same commit. Cache identity includes repository ID, commit SHA, engine and wrapper versions, rules profile/version/hash, coverage policy, and result schema. Mutable names and branch labels remain resolution metadata. Page and popup ref resolutions, public and private, are kept in trusted-only session storage for at most 20 minutes, 100 entries, or 512 KiB, so they survive service-worker restarts; clearing the public cache or changing the connection removes them. Authenticated resolutions for the settings page stay in memory for at most 60 seconds. A confirmed public-to-private transition removes that repository's public resolutions from both. A confirmed public-to-private transition purges persistent results for that repository; unresolved visibility never authorizes a cache display. The service worker keeps only bounded subscriber interruption markers, the latest core API rate limit, and up to 200 automatic-count identities in session storage. Archives and source files are not persisted locally.
- The coordinator permits one active archive analysis, eight queued jobs with a five-minute queue wait, and 32 subscriptions overall. Active jobs have a five-minute deadline, with separate network and worker inactivity watchdogs described in [result semantics](result-semantics.md). The engine owns these duration limits; popup and page viewers have no independent analysis deadline and stop watching on terminal replies, explicit cancellation, navigation, or transport interruption. A subscription belongs to one document/navigation, one repository tab for popup analyses, or the trusted settings page. Service-worker restart reports interruption and requires a new explicit Analyze action; it does not resume an archive download.
- The manifest is explicit in `extension/public/manifest.json`. It declares `storage` and `offscreen` permissions; GitHub, GitHub API, and codeload host access; and a packaged-code CSP that permits local WASM. The existing `github.com` host permission and CSP entry cover the device-flow endpoints, so connecting GitHub adds no permission. The action opens a packaged popup that reads the active tab using the existing GitHub host permission; no `tabs` permission is added. Vite builds the service worker, popup, settings page, offscreen document, analysis worker, and packaged WASM asset. The popup and settings page use Preact components styled with Tailwind CSS; their stylesheet is compiled and packaged locally, and Preact is bundled in a named local chunk. The content script, service worker, offscreen document, and workers load neither Preact nor the stylesheet. Bun bundles the content script as a classic script because Chrome's manifest content-script entry cannot load Vite's split ESM chunks. Neither build path changes the manifest's permissions.
- Chrome 120 is the minimum supported version. Bun 1.4.2 runs the TypeScript build and checks; Cargo runs native Rust tests; direct WASM tests exercise the generated module; and Playwright smoke tests load the packaged extension in Chromium.

The project is licensed under Apache-2.0. The extension icon PNGs in `extension/public/icons/` are generated deterministically from the project-owned `assets/original/culverin-original-stats.svg` with `bun run icons:build`; `bun run icons:check` verifies the committed sizes. The `stats` artwork in every color variant uses the same shape drawn on a 16 by 16 grid, which the generator enforces, so the 16, 32, 48, and 128 pixel icons, the GitHub page row, and the 32 pixel settings heading scale it by whole pixels and keep even line widths. The settings heading shows the light or dark variant to match the color scheme.

Pure repository identity, validation, overview URL parsing, and comparison live in `extension/src/github/repository.ts`; the content adapter owns only DOM discovery and hydration. Popup and Storage share display formatting through `extension/src/ui/format.ts`. These helpers have no browser API or DOM effects at import time.

One offscreen-document manager owns context checks, shared creation, leases for starting and active clients, and idle closing. Archive and diagnostic clients release ownership on completion, cancellation, deadline, or setup failure. A new acquisition invalidates a pending idle check; when closing has already started, setup waits and recreates the document before dispatching work. On service-worker startup, existing archive work is reconciled and interrupted before saved subscriber markers are reported; this does not create an offscreen document when none exists. The manager does not own archive deadlines, credentials, or job restart policy.

The background composition root creates resources and wires authentication, rate-limit tracking, public analysis policy, the trusted settings adapter, popup tab jobs, and page/port transport. Listener registration is explicit and idempotent. Shared request deduplication, pending cancellation, interruption markers, visibility revocation, and failure conversion preserve their existing bounds and keys. Public page/popup and trusted settings retain separate sender gates, resolution policies, reply contracts, and credential selection.

The default background entrypoint registers only production handlers, and `offscreen.html` loads the production archive router. `bun run build` emits `extension/dist` with one archive worker; packaging always reads that directory. `bun run build:test-extension` explicitly selects diagnostic entrypoints under `tests/extension/` and writes a separate ignored `.bun/test-extension` artifact. It composes the same production background, archive parser, and counter with fixture/feasibility handlers, an alternate feasibility worker, and a probe channel. No runtime switch can enable these adapters in a release. Package checks reject diagnostic markers and extra workers.

The archive worker's synthetic delay implementation lives in the diagnostic adapter and is injected into the shared worker core. The bounded `blockMs` field remains in the shared host/bridge protocol for test compatibility; production acquisition sends zero, and the production worker has no delay hook. The WASM `force_trap` export and trusted settings analysis used by the benchmark remain supported. Browser product scenarios and extracted-ZIP checks exercise the actual production artifact; a separate browser profile exercises diagnostic cancellation, leases, traps, fresh memory, and restart recovery. See [browser checks](browser-tests.md).
