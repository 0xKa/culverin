# Loading indicators

Long-running actions share a small spinner. In the popup it appears beside the analysis status; on the repository page it replaces the Culverin icon while counting. Existing phase text and cancellation remain available. Reanalyze starts with “Checking for updates…” and moves to the normal download, unpacking, and counting phases if the commit changed.

In GitHub settings, requesting an approval code shows “Connecting…” inside the disabled Connect button. Once the code appears, the spinner disappears and the static “Waiting for approval on GitHub” message remains. Token validation shows “Checking token…” inside the disabled Save token button. The token field is disabled during validation. Completion or failure restores the controls. The spinner is decorative; status text supplies its meaning, and reduced-motion preferences stop its animation.

## Manual checks

1. Run `bun run build` if the extension has not already been built, then reload Culverin at `chrome://extensions`. Load `extension/dist` if you are setting up an unpacked development copy for the first time. Refresh GitHub tabs and reopen the settings page so all pages use the new build.
2. For requests that finish too quickly to observe, inspect Culverin's service worker from its entry at `chrome://extensions`, then use the DevTools Network panel's throttling menu to choose a slow profile or a custom profile with increased latency. Requests originate in the service worker, so use its DevTools rather than the GitHub tab's. See Chrome's [extension debugging guide](https://developer.chrome.com/docs/extensions/get-started/tutorial/debug) and [network throttling reference](https://developer.chrome.com/docs/devtools/network/reference#throttling).
3. Restore normal networking when you finish testing.

| Action              | Steps                                                                                                                                                                                                    | Expected result                                                                                                                                                                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Analyze repository  | Open a public repository you have not counted, open Culverin, and select Analyze repository. Use a larger repository to make more of the analysis visible.                                               | A spinner appears beside the preparing and subsequent phase text. Analyze is disabled; Cancel analysis remains available. The spinner disappears when results or an error appear. Small repositories can move through phases too quickly to see each one. |
| Count lines of code | Open an uncounted public repository with the About sidebar visible and select Count lines of code.                                                                                                       | The row icon becomes a spinner beside the phase text. Clicking the running row cancels the count. The spinner disappears when the total, retry action, or canceled state appears.                                                                         |
| Reanalyze           | After obtaining a result in the popup, select Reanalyze.                                                                                                                                                 | A spinner appears beside “Checking for updates…”. With no new commit it disappears when the cached-result message appears. If a commit has been added to the default branch, it continues beside the normal analysis phases until the new result appears. |
| Retry               | Open an uncounted repository while online. Switch the service-worker Network panel to Offline, then click Count lines of code. After the failure appears, restore networking and click Retry on the row. | The spinner disappears after the failed attempt and appears again during Retry. The final result removes it. The popup's Analyze action also supports retrying after failure.                                                                             |
| Connect with GitHub | In Settings → GitHub, start from the disconnected state and select Connect with GitHub. Leave the approval code unapproved for a few seconds, then approve it or select Cancel.                          | The button shows a spinner and “Connecting…” only while requesting the code. The code screen has a static waiting message and no spinner throughout polling. Approval shows the connected state; Cancel removes the code.                                 |
| Save token          | From the disconnected state, expand Use a personal access token instead, enter a valid token, and select Save token. Repeat with an invalid value to check failure recovery.                             | The button shows a spinner and “Checking token…”. The field and submission button are disabled while waiting. Success shows the connected state; failure restores the Save token label and controls with an error message.                                |

For cancellation, start a longer analysis and select Cancel analysis in the popup, or click the running repository row. The spinner should disappear immediately. Reopen the popup while an analysis is still running to confirm its spinner and Cancel control return. Enable reduced motion in your operating system, or emulate `prefers-reduced-motion: reduce` in DevTools, and repeat a slow action: the indicator remains visible but does not rotate.
