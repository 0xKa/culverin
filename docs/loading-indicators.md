# Loading indicators

The popup and settings share a dot-grid loader, where a diagonal wave sweeps across a 5×5 grid. Analyze repository and Reanalyze both hide their button and show the loader centered in its place, with a small Cancel analysis button below it; focus moves to Cancel and returns to the analysis button when the analysis ends. On the repository page, a small spinner replaces the Culverin icon while counting. Existing phase text and cancellation remain available. Reanalyze starts with “Checking for updates…” and moves to the normal download, unpacking, and counting phases if the commit changed.

In GitHub settings, requesting an approval code shows a small dot-grid loader and “Connecting…” inside the disabled Connect button. Once the code appears, the loader disappears and the static “Waiting for approval on GitHub” message remains. Token validation shows the loader and “Checking token…” inside the disabled Save token button. The token field is disabled during validation. Completion or failure restores the controls. The spinner and dot-grid loader are decorative; status text supplies their meaning, and reduced-motion preferences stop their animation.

## Manual checks

1. Run `bun run build` if the extension has not already been built, then reload Culverin at `chrome://extensions`. Load `extension/dist` if you are setting up an unpacked development copy for the first time. Refresh GitHub tabs and reopen the settings page so all pages use the new build.
2. For requests that finish too quickly to observe, inspect Culverin's service worker from its entry at `chrome://extensions`, then use the DevTools Network panel's throttling menu to choose a slow profile or a custom profile with increased latency. Requests originate in the service worker, so use its DevTools rather than the GitHub tab's. See Chrome's [extension debugging guide](https://developer.chrome.com/docs/extensions/get-started/tutorial/debug) and [network throttling reference](https://developer.chrome.com/docs/devtools/network/reference#throttling).
3. Restore normal networking when you finish testing.

To check Reanalyze recovery, collapse Analysis details, then select Reanalyze with slow networking and cancel while it is waiting. Repeat with the service-worker Network panel set to Offline. Both attempts should remove the loader, show and enable Reanalyze, and retain the previous result and collapsed details. Restore networking, add a commit to a test repository’s default branch, and reanalyze again: the old commit stays displayed until the new result is ready.

For cancellation, start a longer analysis and select Cancel analysis in the popup, or click the running repository row. The loader or spinner should disappear immediately. Reopen the popup while an analysis is still running to confirm its loader and Cancel control return. Enable reduced motion in your operating system, or emulate `prefers-reduced-motion: reduce` in DevTools, and repeat a slow action: the indicator remains visible but does not animate.
