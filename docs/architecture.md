# Architecture decisions

Culverin is a browser-local Chrome Manifest V3 extension. GitHub supplies repository metadata and source archives; the extension analyzes source in the browser. There is no Culverin server, native companion, or telemetry service.

## Extension boundaries

- The TypeScript service worker owns GitHub requests, credentials, job coordination, and cancellation. Packaged settings-page controls, the extension popup, and GitHub content-script controls have separate sender gates. Public page requests must come from a top-level GitHub document and match the tab's current repository overview URL, which can change within the same document. Popup requests and replies travel on a long-lived port that the service worker accepts only from the packaged `popup.html`, whether Chrome shows it as the toolbar popup or in a tab. Chrome omits frame and document IDs for the toolbar popup, so the port itself identifies the popup; the popup reconnects on its next request after a service-worker restart. Lookup, status, and Analyze requests are checked against the active GitHub repository tab; a cancel request only needs to name that tab's running popup analysis, so switching tabs neither cancels the analysis nor prevents a later cancel. The service worker does not accept token submissions, so no credential can be activated; the remaining session disconnect and clear controls are settings-only. The worker binds each subscription to its tab or extension document, navigation, and request IDs.
- The GitHub content script adds one Shadow DOM row to the About list on supported repository overviews, including URLs with fragments. The script runs at `document_start` and starts the lookup as soon as GitHub's repository marker in the document head names the current repository, so metadata resolution overlaps page loading; the About forks row is a fallback trigger for same-document navigation. A page adapter anchors the row after the visible About forks row, and waits until GitHub's enclosing React app is marked loaded so the row never interferes with hydration; when the About sidebar is hidden, as in narrow layouts, no row is shown. The row uses GitHub's color variables and the pixel-aligned monochrome icon [`assets/mono/culverin-mono-stats.svg`](../assets/mono/culverin-mono-stats.svg), bundled into the content script and drawn in `currentColor`, so it matches the neighboring repository stats, with a compact total and the exact total in its tooltip. Fragment changes and GitHub sidebar re-renders keep the same view and move the row back into place. A bounded URL check detects same-document route changes even without DOM mutations; DOM mutations and window resizing remain recovery signals. When the local cache holds no complete result for the page's owner and name under the current rules, a page lookup makes no GitHub request and the row offers to count lines of code; if an earlier request hit the rate limit and its retry time has not passed, the row shows the rate-limit notice instead. Otherwise the lookup resolves metadata and may show a compatible complete cached total without downloading an archive, or offers to count when the commit or rules no longer match. A Counting setting can instead count when the page opens: the lookup then always resolves metadata, and on a cache miss the service worker tells the content script to start the same analysis a click would. It does so at most once per repository, commit, and rules per browser session, tracked in session storage and reset by clearing the public cache, so a failed, partial, or canceled count is not repeated on every visit. A trusted click on that row, like the popup's Analyze action, permits a SHA-specific source snapshot download. While a page analysis runs, the row shows its progress and a trusted click cancels it. A trusted click on a complete total asks the service worker to open the toolbar popup for the active tab with `chrome.action.openPopup`, which needs no extra permission; on Chrome versions before 127, where extensions cannot open their popup, the click has no effect. A failed analysis offers a retry, a rate limit shows a notice until its retry time, and size limits, unsupported snapshots, and partial results show a notice without a total. A lookup that resolves a private, unavailable, or empty repository hides the row. The toolbar popup contains the full analysis UI; its explicit Analyze action permits a SHA-specific source snapshot download. Opening the popup makes no GitHub request: its lookup reads only resolutions kept from the last 20 minutes. Without one, the popup shows the repository name and Analyze, and Analyze resolves metadata before counting. Once a result is shown, the button reads Reanalyze; Reanalyze resolves metadata again even within the 20-minute window, shows the cached result when the commit and rules are unchanged, and otherwise downloads and counts the new commit. Alongside code lines, the popup shows text lines, the prose lines of documentation formats defined in [result semantics](result-semantics.md). The popup header shows how many unauthenticated core API requests remain out of the hourly limit, such as `API 57/60`. The service worker reads the count from the `x-ratelimit-*` headers of its public lookup responses, including rate-limited ones, so showing it costs no extra request; it keeps the lowest count seen for the current reset window, and the popup shows the full limit once the reset time passes. Archive downloads are not counted, because GitHub tracks them separately from the core limit. When a kept resolution exists, the popup shows the repository size that GitHub reports in its metadata, which includes Git history and needs no archive download; an analysis result, including a cached one, adds the total size of the regular files at the analyzed commit. A popup analysis belongs to its repository tab rather than to the popup document: closing the popup does not cancel it, and a reopened popup on the same tab resumes its progress and result through `analysis.status`. Navigating that tab away from the repository or closing it cancels the analysis. After a complete result, the service worker sends the code-line total to the matching repository page. The content script can read a compatible public aggregate cache result or its own page analysis result, but renders only the code-line total and never receives credentials, archive URLs, or source files. The packaged settings page exposes the Culverin ignore settings, the public cache control in its Storage section, and in its Counting section whether counting starts on an explicit action, the default, or when a repository page opens. The Counting choice is stored in trusted-only `chrome.storage.sync` only when it differs from the default. A sidebar switches between sections through the URL fragment, such as `settings.html#storage`. Without a known fragment, the page opens the section last shown, which it keeps in the extension origin's `localStorage`, or else the first sidebar section; the popup's Culverin ignore Edit action selects that section before opening the page. The service worker ignores the fragment when it checks that a request comes from the settings page. Culverin ignore turns built-in exclusion groups on or off and adds custom exclusions; the settings page writes them to `chrome.storage.sync`, restricted to trusted extension contexts. The service worker reads the current settings for each lookup and analysis, uses their rules hash for cache and job identity, and passes the rules to the analysis worker; results counted under other settings remain cached but are not shown. When the settings differ from the defaults, the popup summarizes them with a link to the settings page, and a lookup that finds only results counted under other settings says that the rules changed. The content script never reads the settings; it compares a result's rules hash with the default hash only to add a Culverin ignore note to the row's tooltip.
- Public page messages use a closed version-1 request and reply protocol. A lookup returns a cache hit or miss after a compatible resolution confirms public visibility; a page lookup without a cached result returns `repository.not_cached` without resolving, and a cache miss may carry `autoCount` when the Counting setting counts on page open. A popup lookup never resolves: it returns a cache hit or miss from a resolution kept in the last 20 minutes, or `repository.not_cached` without one. Only popup analysis requests may carry `reanalyze: true`, which bypasses the kept resolution. A page may also ask the service worker to open the toolbar popup; the popup port rejects that request. Resolution metadata, including its timestamp and GitHub's reported repository size, lives outside the deterministic result. Both worker and page validate result identity against the resolution before display. One archive analysis runs at a time; identical explicit requests share it, while distinct requests wait in a bounded queue. Public page analysis uses unauthenticated GitHub requests and does not display private-repository results.
- An offscreen document hosts a dedicated, terminable analysis worker. The service worker transfers bounded archive chunks to it with acknowledgments. The worker decompresses gzip, validates tar entries, applies file limits, and calls a fresh Rust/WASM counter for each job. The service worker receives the aggregate result and transport diagnostics, not source files.
- The Rust counter uses Tokei and exposes the same counting boundary to native tests and browser WASM. The result contract is [`schemas/analysis-result-v2.schema.json`](../schemas/analysis-result-v2.schema.json). Counting rules, coverage, archive handling, and resource limits are specified in [result semantics](result-semantics.md). An interrupted, canceled, malformed, or resource-limited job returns a failure rather than a complete result.

## Storage and packaging

- Culverin analyzes public repositories only and makes unauthenticated GitHub requests. Credential session state is restricted to trusted extension contexts through `chrome.storage.session`. Culverin ignore settings are stored in trusted-only `chrome.storage.sync`, which Chrome syncs with the user's other browsers when Chrome sync is on. Complete public aggregate results are stored in trusted-only `chrome.storage.local`, bounded to 200 entries or 5 MiB. Cache identity includes repository ID, commit SHA, engine and wrapper versions, rules profile/version/hash, coverage policy, and result schema. Mutable names and branch labels remain resolution metadata. Public ref resolutions are kept in trusted-only session storage for at most 20 minutes, 100 entries, or 512 KiB, so they survive service-worker restarts; clearing the public cache removes them. Authenticated resolutions for the settings page stay in memory for at most 60 seconds. A confirmed public-to-private transition removes that repository's resolutions from both. A confirmed public-to-private transition purges persistent results for that repository; unresolved visibility never authorizes a cache display. The service worker keeps only bounded subscriber interruption markers, the latest core API rate limit, and up to 200 automatic-count identities in session storage. Partial results, private results, archives, and source files are not persisted locally.
- The coordinator permits one active archive analysis, eight queued jobs with a 30-second queue wait, and 32 subscriptions overall. A subscription belongs to one document/navigation, one repository tab for popup analyses, or the trusted settings page. Service-worker restart reports interruption and requires a new explicit Analyze action; it does not resume an archive download.
- The manifest is explicit in `extension/public/manifest.json`. It declares `storage` and `offscreen` permissions; GitHub, GitHub API, and codeload host access; and a packaged-code CSP that permits local WASM. The action opens a packaged popup that reads the active tab using the existing GitHub host permission; no `tabs` permission is added. Vite builds the service worker, popup, settings page, offscreen document, analysis worker, and packaged WASM asset. The popup and settings page use Preact components styled with Tailwind CSS; their stylesheet is compiled and packaged locally, and Preact is bundled in a named local chunk. The content script, service worker, offscreen document, and workers load neither Preact nor the stylesheet. Bun bundles the content script as a classic script because Chrome's manifest content-script entry cannot load Vite's split ESM chunks. Neither build path changes the manifest's permissions.
- Chrome 120 is the minimum supported version. Bun 1.4.2 runs the TypeScript build and checks; Cargo runs native Rust tests; direct WASM tests exercise the generated module; and Playwright smoke tests load the packaged extension in Chromium.
