# Counter result semantics

Culverin counts selected in-memory files with Tokei 15.0.0. The deterministic result contract is [`schemas/analysis-result-v2.schema.json`](../schemas/analysis-result-v2.schema.json); the `counter/src` Rust modules produce it and `extension/src/counter/result.ts` validates its structure and cross-field invariants. Results identify Tokei, wrapper version `3`, the `source-v1` rules profile, rules version `2`, and coverage policy version `2`. They are Tokei results. They are not normalized to `cloc` or GitHub Linguist, which use different recognition and counting policies.

## Input and attribution

The boundary accepts relative slash-separated paths and bytes. It rejects empty, absolute, dot-segment, backslash, NUL, and overlong paths. `classify_path` uses a bounded prefix to detect paths and shebangs; `add_file` repeats classification and inspects the full body for NUL bytes. Ordinary NUL-containing files are binary skips. UTF-16 BOM files are decoded first, so their NUL bytes do not make them binary; a UTF-16 BOM file that does not decode cleanly, such as one with an unpaired surrogate or an odd byte count, is a binary skip. UTF-8 BOM is stripped. Other files reach Tokei as raw bytes, as in Tokei's own file reader, so malformed UTF-8 is counted exactly: Tokei matches only ASCII line breaks, whitespace, and syntax tokens, which invalid bytes can neither form nor hide. Notebooks are read by the wrapper rather than Tokei's notebook parser, which rejects valid notebooks with raw cells, string sources, or missing kernel metadata. The wrapper accepts any JSON object with a `cells` array whose cells have a `cell_type` and a `source` given as a string or a list of strings. It picks the code language as Tokei does, from `kernelspec.language`, then `language_info.file_extension`, then Python, and counts each code cell in that language and each markdown cell as Markdown; raw and unknown cells are not counted. A notebook that does not have that shape, including invalid JSON and nbformat 3 notebooks, is skipped as `unsupported_notebook`.

One eligible regular file increments `countedFiles` and exactly one language row's `files`: its primary Tokei language. Child rows for embedded languages always have `files: 0`. The counter attributes child lines to their child language. For HTML, Vue, and Svelte, Tokei counts the lines inside a multi-line embedded block only in the child language, while a physical line shared by parent markup and embedded code counts in both. When a file's attributed lines exceed its physical lines, the wrapper removes the excess from the primary language, taking code first, then comments, then blanks, so child attribution takes precedence. Each notebook cell is counted on its own with the same rule, and its lines go to the cell's languages; the notebook's own row has the file but no lines. Wrapper version `2` introduced the rule for embedded blocks; version `1` subtracted child counts for HTML, Vue, and Svelte too, which undercounted multi-line blocks or failed the analysis. Wrapper version `3` counts notebook cells itself; version `2` counted fenced code in markdown cells twice and marked such results `counter_inaccurate`, and it marked malformed UTF-8 the same way, which coverage policy version `2` removes. Markdown already separates fenced child lines from its own lines. This produces one physical line total per text file in the accepted corpus while preserving Tokei's code, comment, and blank classifications as far as possible. Notebook cell source lines are logical source lines rather than lines of notebook JSON. Empty files still count as one file with zero lines; whitespace-only files count blank lines.

The accepted corpus includes Rust, TypeScript, Markdown fences, HTML, Vue, Svelte, notebooks with markdown fences, raw cells, and string sources, unreadable notebooks, extensionless Python shebangs, UTF-8 BOM, UTF-16, malformed UTF-16, malformed UTF-8, binary data, empty files, and built-in and custom exclusions. Native and browser-WASM runs consume the same path, byte, and rules fixtures. Unknown extensions and unrecognized extensionless files are `unsupported_language`, reported as other files below; one that contains a NUL byte anywhere is a binary skip instead. `oversized_source` marks an eligible file above 8 MiB as skipped and makes coverage partial; it is the only reason a result is partial. A partial result still carries exact totals for the files it counted, is cached like a complete one, and is shown with a note saying how many files were too large to count. Excluded, unsupported, binary, and unsupported notebook files do not make coverage partial. Other failures, including traps and invalid inputs, do not return a result.

`analyzedBytes` totals the bytes of counted files. `totalBytes` totals the bytes of every regular file in the snapshot, whether it is counted, excluded, unsupported, binary, or oversized, so it does not depend on the rules profile or custom exclusions. A streamed skip reports the tar entry's effective size, which must be at least the length of its classification prefix. Directories, symbolic links, hard links, and other non-regular entries contribute no bytes, and tar headers and padding are not included. `totalBytes` is never less than `analyzedBytes` and equals it when no file is skipped. Schema version 2 introduced `totalBytes`; stored results from earlier schema versions fail validation and are discarded.

Tokei records prose in literate formats as comment lines, so Markdown, MDX, Djot, and Plain Text contribute no code lines except through fenced code blocks, which count toward the fenced language. The popup reports text lines separately from code lines: the sum of the comment lines in those four language rows. Its details list code languages and text formats in separate sections, each opened by the section's total lines and files and ordered by lines, then files, then name. Text lines are derived from the result for display and are not a result field.

`otherFiles` describes the regular files that are not recognized as a language. They are not counted by Tokei and are not part of the totals, the language rows, code lines, or text lines; they remain `unsupported_language` skips, and `otherFiles.files` equals that skip count. Each one is read as bytes while it streams and contributes its physical lines: the number of line feeds, plus one when the file is not empty and does not end with a line feed. Files are grouped by the text after the last `.` of the file name, lowercased and kept with its dot, such as `.golden`, `.gitignore`, or `.yml~`. A name without a dot, ending with a dot, or whose text after the last dot is longer than 16 characters or contains a space or control character is grouped as an empty extension, shown as No extension; such text, like a version or hash, is not a file type. `extensions` keeps at most the 100 groups with the most lines, then the most files, then by extension in code point order, and `moreExtensions` counts the groups past that cap. Without more groups, the rows add up to the `otherFiles` totals. The popup lists the rows in an Other files section in that order, under the section's total lines and files. It shows the first 10 and keeps the rest behind a Show more toggle, which ends with a row such as `3 more extensions` for the files and lines of groups past the cap. Formats that Tokei counts as code, such as reStructuredText and AsciiDoc, stay in code lines and are not text lines.

## Rules and identity

The profile excludes five built-in groups: `dependencies`, `build` output, `environments` and caches, `lockfiles`, and `minified` files and source maps. The exact current lists are in `extension/src/counter/rules.ts` and mirrored at the Rust boundary. Matching uses exact components, basenames, and the declared suffixes below. `.gitignore` is not read. Directories such as `vendor` and `build` can contain original work, so Culverin ignore settings can turn off any built-in group and add custom exclusions. Every group is on and no custom exclusion is set by default.

Custom exclusions are capped at 64 rules, 256 bytes per rule, and 4096 total bytes. Custom exclusions and disabled groups are each sorted and deduplicated, and unknown groups are rejected. The effective rules hash is SHA-256 of the UTF-8 JSON encoding of `["source-v1","2",disabledGroups,normalizedExclusions]`. The cache identity includes schema version, counter name and version, wrapper version, rules version and hash, and coverage policy version, so results counted under different Culverin ignore settings are kept apart and reused when the same settings return. Changing any counting or classification policy requires an appropriate version bump. Result fields retain no paths, timestamps, or transport metrics.

## Archive processing

An explicit analysis request resolves the default branch to a full commit SHA and streams that revision's GitHub tar.gz archive. The service worker owns the request and credentials. Bounded chunks pass to a packaged, terminable worker through the offscreen host; the worker decompresses gzip, validates tar, and invokes one fresh WASM analyzer per job. The extension retains at most one eligible regular-file body at a time. It does not store the archive or source files. A lookup alone does not download an archive.

The parser supports USTAR headers and length-prefixed PAX records. Supported effective PAX keys are `path`, `linkpath`, and `size`. Harmless metadata keys are `mtime`, `atime`, `ctime`, `uid`, `gid`, `uname`, `gname`, `comment`, `charset`, `SCHILY.dev`, `SCHILY.ino`, and `LIBARCHIVE.creationtime`; they do not affect counting. Unknown keys, including sparse-file metadata, are rejected. Duplicate keys in one PAX body are rejected. Global values apply to later entries, local values apply to exactly the next non-PAX entry, and local values take precedence. An empty global value removes that global key; an empty local effective value uses the USTAR header value for that entry. Effective size is interpreted before reading the body. Octal and non-negative base-256 header numbers are supported; overflow, negative values, invalid checksums, nonzero padding, truncated records, and missing two-block zero terminators fail. Any bytes after the terminator must be zero.

Header strings and PAX records use strict UTF-8. All USTAR numeric fields, including ignored ownership, mode, time, and device fields, are validated on every entry. Paths are normalized by removing repeated separators and `.` components, after rejecting any `..` component, NUL, backslash, absolute, drive, or UNC form. Every entry must share one wrapper directory; the wrapper-root directory itself is ignored. Duplicate normalized logical paths are rejected. Directories, links, devices, FIFOs, and other supported special entries are validated and ignored, never followed. Link targets are never resolved, so a symbolic or hard link may point to a parent directory, an absolute path, or a missing file; only a target containing NUL or longer than 4,096 UTF-8 bytes fails. A Git submodule appears in the snapshot as an empty directory, so its contents are not counted. Unsupported entry types fail. The parser retains only normalized paths during a job for duplicate detection and drops them afterward.

The declared limits are 50 MiB compressed response, 250 MiB decompressed data, 50,000 tar entries, 40,000 regular files, 8 MiB per buffered eligible source file, 200 MiB passed to WASM, 4,096 UTF-8 path bytes, 100 path components, 64 KiB per PAX body, 2 MiB cumulative PAX bodies, and 8 MiB retained normalized-path bytes. Browser stream chunks have no size limit of their own, because their size depends on timing rather than on the archive; the service worker splits each one into acknowledged transfer chunks of at most 64 KiB. Each limit is enforced while streaming. A recognized eligible source above 8 MiB is discarded and recorded as `oversized_source`, making coverage partial. Excluded, unsupported, binary, and unsupported notebook regular files are counted as semantic skips but do not make coverage partial. Global limits, malformed or unsupported archives, cancellation, interruption, and counter errors return failure with no result. A failure caused by a global limit names that limit in its message, such as `The limit is 40,000 files.` Compressed/decompressed byte counts, entry counts, and the sampled maximum WASM linear-memory size are diagnostics, separate from deterministic result fields.

An active analysis has a five-minute overall deadline beginning when its queued job starts; metadata resolution retains its separate bounded request timeout. Obtaining the archive response or waiting for its next network chunk may take at most 30 seconds. The offscreen host terminates a worker after 60 seconds without actual stream or counting activity, even while service-worker leases continue. The worker reports decompressed-byte consumption and counting activity; lease renewal alone never extends the work watchdog. A three-second missing lease still marks the job interrupted. Queued jobs may wait up to five minutes before failing as busy. Cancellation terminates the worker, and an overall deadline is reported as a timeout rather than cancellation.

The built-in `source-v1` matcher is case-sensitive. The directory names listed in `extension/src/counter/rules.ts` match whole path components; listed lockfiles match whole basenames; `.map`, `.min.js`, and `.min.css` match basename suffixes. A custom exclusion takes one of four forms: `*.ext` matches basenames ending in `.ext`; a name without `/`, such as `schema.graphql` or `fixtures`, matches any path component with that exact name; a single name ending in `/`, such as `fixtures/`, matches only folders with that name; and a path containing `/`, such as `docs/generated`, matches that path from the repository root and everything under it, or only what is under it when it ends in `/`. Custom exclusions are case-sensitive. They reject empty rules, a leading `/`, backslashes, NUL, `?`, any `*` other than a leading `*.` followed by a non-empty ending without `/`, and `.`, `..`, or empty path components. Matching happens at the Rust counter boundary, including for stream-discarded entries. Rules version `2` adds recognition of well-known extensionless documents. When a file name has no dot, is not a recognized build file, and has no recognized shebang, the names `README`, `LICENSE`, `LICENCE`, `COPYING`, `NOTICE`, `AUTHORS`, `CONTRIBUTORS`, `CHANGELOG`, `CHANGES`, `HISTORY`, `NEWS`, and `VERSION`, and names starting with `LICENSE-` or `LICENCE-`, are counted as Tokei's Plain Text, matching case-insensitively. Other extensionless files without a shebang remain `unsupported_language`.

## Browser dependency

Tokei is pinned to the exact crates.io release `15.0.0` with CLI features disabled. Its transitive `home` 0.5.12 crate lacks a `wasm32` fallback, so [`patches/home`](../patches/home) is a copy of that crate with one target-specific `home_dir_inner()` implementation returning `None`. The crate's MIT and Apache licenses are preserved. Remove the patch when upstream `home` supplies a browser-target fallback and Tokei can compile unchanged. The `wasm-bindgen` glue has a singleton initialization guard; the build script copies generated glue and removes only that guard so each serialized job instantiates fresh WASM memory. The generated source remains untouched.
